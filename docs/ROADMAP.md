# Roadmap

## 当前阶段（2026-10-09）

晚间用户由有线切到 WiFi 后再次出现慢发送和 AudioQueueOverflow（积压 5 秒、丢弃 9 块），不是交接取消复发；网络根因尚未确认，优先做同版本／同 VPN 条件的有线对照。错误提示已增加仅隐藏 HUD 的关闭入口，独立 tsf-error-dismiss 构建及 56 项 C# 测试通过，真实鼠标关闭与焦点表现待用户确认；不自动恢复录音，未改音频或输入链路。识别错字／断句样本已记录，暂不进入整理功能。

预连接交接修复已通过三轮有限真实复测：用户确认启动识别、快捷键停止及文字保留均正常，唤醒主观较快。日志三轮 session_error 为 0，均有 partial / stable 写入确认；会话开始到录音启动约 1906、68、69 ms，不能外推为每次即时启动。新版本 tsf-warm-handoff 已通过 Release 构建（0 警告／错误）、55 项 C# 与 65 项 Python 测试。识别不准确仍待排查，下一步先取得预期文本与实际识别对照；网络卡顿及真实讲话到出字延迟仍未结案。详细证据见 TESTING 最新章节。

接收调度诊断已完成最小实现及本地验证，真实语音待测。经授权恢复项目本地 SDK 10.0.400／runtime 10.0.11，无全局安装；独立 `tsf-receive-timing` 构建 0 警告／错误，51 项 C# 与 65 项 Python 测试通过。新增接收完成观测与客户端恢复执行计时，不改识别协议、音频或接管策略。此前 9 月 21 日真实测试结论仍按下述边界保留，不等同于新版已完成真实测试。

项目处于 Phase 6 真实输入联调阶段。切换 VPN 后，记事本与 Chrome 内 ChatGPT 输入框的有限场景已通过真实测试；下一步定位讲话到目标框出字的延迟。原网络条件下的间歇慢发送仍未解决，没有进入 AI 整理、语音编辑或外部 Beta 阶段。

本文只维护进度、阻塞和下一步。详细历史与命令保留在 [TESTING](TESTING.md)，设计见 [ARCHITECTURE](ARCHITECTURE.md)，产品范围见 [PRODUCT_SPEC](PRODUCT_SPEC.md)，取舍见 [DECISIONS](DECISIONS.md) 。当前新增诊断不代表已经消除延迟或网络问题。

此前文档设计的 Claude 外部复核未完成，历史原因见 TESTING。本次按用户要求不使用 Claude 复核；后续设计仍不等同于已实施能力。

## 主要阻塞

1. **原网络间歇慢发送根因未定。** v2 复现卡顿，也显示 Python 快速 send 后可能存在底层缓冲。用户切换 VPN 后一组发送正常、结束确认降至 33–70 ms；同时代理解析及 Python 地址族发生变化。支持网络路径影响显著，不是手机热点实验，不证明代码已修复或 VPN 必然更快。
2. **实时跟随延迟待定位。** 用户已说四字、目标框仅出三字时接管，会只保留已显示三字。现有日志分析已完成：Chrome 基础轮收到文字到写入确认中位约 26 ms，而同段 partial 返回间隔中位约 503 ms；接管样本也存在取消约 14 ms 后才到达的新 partial，未补写。下一步聚焦收到识别结果之前的路径；尚不能分离真实语音起点、网络、服务端等待和客户端接收调度，也不以写入确认代替屏幕可见。
3. **验收范围仍有限。** 当前 VPN 下已检查会话有 Notepad 8 个 stable、Chrome 2 个 stable，多段写入已获得真实证据；不再标为完全未测。重复启停、闲置后重新连接已获用户确认，但冷启动仍有等待，中英识别准确率、更长压力测试和其他应用未完成验收。
4. **旧 native 激活测试仍失败。** legacy direct activation harness 的 `E_INVALIDARG` 与已通过的 31 项 live 检查分开报告，不以局部通过代替全套通过。

## 下一步：定位讲话到出字的延迟

现有日志审计及最小接收计时已完成，交接修复三轮真实复测通过。先收集用户反馈的准确度对照样本，不立即修改模型或参数；以下延迟验证仍待完成：

1. 保持当前已测网络、模型、100 ms chunk 和输入模式不变。优先定位 ASR 结果到达之前的路径，不先改 TSF 写入或用插字动画掩盖更新间隔。
2. 按 TESTING 新版命令在已设 Key 的 PowerShell 启动，在记事本正常说约 20 秒、留一次停顿，不做键鼠干扰，停止后分析同一 task/message_seq 的接收完成观测、恢复执行、解析和写入。计时不代表 TCP 包到达；若恢复延迟小，仍需区分上游和未观测的本地调度，不能直接断言模型慢。chunk_captured 仍是出队日志，真实讲话起点和屏幕可见时间仍未测量；不默认录屏或保存音频。
3. 先确定慢在哪一步，再提出针对性调整；不得预先假定是模型、网络或 TSF，不以增加缓冲、接管后继续补字掩盖问题。不默认录屏或保存原始音频。

Phase 6 保持进行中，详细证据和用户反馈见 TESTING 最新章节。不得自动重放不确定写入、切换目标补写，也不新增 AI 功能、应用适配或 HUD 错误自动隐藏功能。

## 后续顺序（尚未实施）

每项单独界定范围和验收，以下不是一次性开发授权：

| 顺序 | 目标 | 进入条件 |
| --- | --- | --- |
| 1 | 稳定连续输入、明确录音／错误反馈 | 完成当前发送积压和多段输入验证 |
| 2 | 最近稳定结果可主动复制；手动个人词典 | 主链路稳定后分别设计；确定内存上限、清除规则和供应商热词能力，不默认存音频 |
| 3 | 基础 Document Engine、目标同步、局部替换与 Undo | 已验证目标身份、选区／版本及人工修改冲突处理 |
| 4 | 默认 None、可选 Light；明确选区／简单替换语音编辑 | 第 3 项具备后；整理不得阻塞显示或覆盖人工修改 |
| 5 | 更复杂引用、保守的 Voice Send、按需应用适配 | 简单编辑可靠；发送意图和目标规则分别验收 |
| 6 | 小规模外部 Beta、安装分发及必要后端 | 核心体验通过；供应商密钥保护与数据边界先完成 |
